1. 왜 add · commit · push 세 단계로 나눌까?
한 문장으로: git add는 "무엇을 이번에 기록할지 고르는" 단계이고, commit은 "내 컴퓨터에 스냅샷을 남기는" 단계이며, push는 "네트워크를 통해 GitHub에 보내는" 단계입니다. 세 단계를 분리한 이유는 Git이 분산 버전 관리 시스템이기 때문입니다. 내 컴퓨터의 작업 디렉터리 자체가 완전한 저장소이고, 모든 commit은 즉시 로컬에 기록되며, push는 네트워크가 필요하고 "공유하고 싶을 때만" 수행합니다.

add를 따로 두는 핵심 이유: 폴더에는 올릴 파일과 올리면 안 되는 파일(.env, 연습용 파일 등)이 섞여 있습니다. add는 올릴 것만 "다음 commit에 포함할 목록"(staging area)에 넣고, commit 전에 git status의 초록색 목록으로 한 번 더 확인할 수 있습니다.

push를 따로 두는 이유: commit은 로컬 작업이라 네트워크가 필요 없고, 몇 번을 해도 비용이 없습니다. push는 "정리 다 했다" 싶을 때 한 번만 하면 됩니다. 그래서 로컬에서 마음껏 commit할 수 있고(저장 지점이 많을수록 좋음), GitHub에 보내는 것은 마지막에 한 번만 합니다.

2. commit과 push는 각각 무슨 뜻인가?
commit (커밋)
무엇을 남기는가: staging area(staged 상태)에 있는 내용의 스냅샷을 프로젝트 이력에 기록합니다. GitHub 공식 문서의 비유: commit은 사진 찍기와 같습니다. git add로 staged된 내용이 commit 시점에 스냅샷의 일부가 됩니다.

왜 메시지를 함께 적는가: commit message는 "이 사진이 무엇인지"를 설명합니다. 나중에 이력(git log)을 볼 때, 메시지가 없으면 어떤 변경인지 알 수 없습니다. 메시지는 한국어로 적어도 됩니다.

중요한 세부 사항: 파일을 수정한 후 다시 git add를 해야 수정한 내용이 다음 commit에 포함됩니다. commit은 staging area의 내용만 기록하며, unstaged된 수정 사항은 포함되지 않습니다.

push (푸시)
무엇을 어디로 보내는가: 로컬 저장소에 이미 commit된 기록을 원격 저장소(예: GitHub의 origin)의 해당 브랜치로 업로드합니다.

주의: git add는 GitHub에 올리지 않습니다(로컬에서 선택만 함). git commit도 GitHub에 올리지 않습니다(로컬에만 기록). GitHub에 실제로 도달하는 것은 git push뿐입니다.

첫 push 시 로그인 창이 뜰 수 있습니다. "Sign in with your browser"를 클릭하고 브라우저에서 승인하면 됩니다. 끝에 main -> main이 보이면 성공입니다.

3. untracked · tracked · staged 세 가지 상태
이 세 단어는 git status의 세 가지 제목에 대응하며, "지금 어떤 파일이 올라갈 예정이고 어떤 파일이 안 올라가는지"를 읽는 핵심입니다.

상태	git status 제목	색상	의미	지금 commit하면
untracked	Untracked files:	빨강	Git이 한 번도 기록한 적 없는 새 파일	포함 안 됨
tracked, modified	Changes not staged for commit: (modified:)	빨강	이전에 commit한 적 있는데, 그 후 수정했고 아직 add하지 않음	수정 내용 포함 안 됨
staged	Changes to be committed:	초록	git add로 다음 commit에 넣기로 선택한 파일	포함됨
tracked란 "Git이 이 파일을 기억하고 있다"는 뜻입니다. 한 번이라도 commit된 파일은 모두 tracked입니다. 수정한 후 add하지 않으면 modified(빨강)로 표시되고, 수정하지 않았으면 git status에 나타나지 않습니다.

stage는 동사로 "다음 commit에 넣을 파일로 고른다"는 뜻입니다. git add가 바로 stage하는 명령이고, 선택된 파일들이 모여 있는 곳을 staging area라고 부릅니다.

파일이 거치는 순서(페이지의 표를 기억하면 됨):

text
새 파일 → untracked(빨강)
git add → staged(초록)
git commit → tracked, 바뀐 것 없음 (status에 안 나옴)
파일 고침 → tracked, modified(빨강)   ← 4
git add → staged(초록)                ← 5 (중요: 고친 뒤 다시 add)
git commit → tracked, 바뀐 것 없음
4→5가 핵심: 한 번 commit한 파일이라도, 수정한 후에는 다시 git add해야 수정한 내용이 다음 commit에 들어갑니다.

착각	실제

5. 실습 시 꼭 지켜야 할 두 가지 안전 규칙
git status에서 .env가 보이면 즉시 멈추기. 키가 GitHub에 올라가면, 나중에 삭제해도 이력에 남습니다. 먼저 .gitignore에 .env와 .venv 두 줄이 있는지 확인하세요.

초록색 목록에 잘못된 파일이 들어갔을 때: git restore --staged 파일이름으로 선택만 취소합니다(파일 내용은 삭제되지 않음). 그런 다음 다시 git status로 빨간색으로 돌아왔는지 확인합니다.
