찾아보고 알게 된 것
보안 담당자가 패킷을 직접 열어 보는 이유는
자동화된 경보(방화벽·IDS·EDR)는 "뭔가 이상하다"까지만 알려주고, 실제로 무슨 일이 일어났는지는 알려주지 않기 때문입니다. 패킷을 직접 열면 경보가 진짜인지 검증하고, 공격자가 구체적으로 무엇을 했는지, 데이터가 유출됐는지, 어디까지 침투했는지를 바이트 수준에서 확인할 수 있습니다. 관제 업무에서는 의심스러운 연결 추적, 악성코드 트래픽 특징 식별, 데이터 유출 평가, 프로토콜 이상 탐지, 엔드포인트 로그와 결합한 공격 타임라인 구축에 씁니다. 단, Wireshark는 수동 분석 도구라 스스로 경보를 울리지는 않는 "디지털 현미경"입니다.

패킷은
네트워크로 데이터를 보낼 때 큰 덩어리를 그대로 보내지 않고 작은 조각으로 나눠 보내는데, 그 작은 조각 하나하나를 패킷이라고 합니다. 각 패킷은 제어 정보(헤더: 보낸 사람 IP, 받는 사람 IP, 오류 검사 코드 등)와 실제 데이터(페이로드)로 구성됩니다. 받는 쪽은 조각들을 받아서 다시 조립합니다.

Npcap 은
Windows에서 Wireshark가 실제로 네트워크 카드의 트래픽을 캡처할 수 있게 해주는 드라이버/라이브러리입니다. Windows는 소프트웨어가 직접 네트워크 카드 원시 데이터를 읽는 것을 허용하지 않아서 이 중간 다리가 필요합니다. Wireshark 3.0 이후 Windows 버전 설치 시 기본으로 함께 설치되며, 이것이 없으면 Wireshark는 실시간 캡처를 못 하고 저장된 캡처 파일만 열 수 있습니다.

| (파이프) 는
앞 명령의 출력 결과를 뒤 명령의 입력으로 넘겨주는 연결 통로입니다. tasklist | findstr Code처럼 쓰면 tasklist 결과를 findstr이 받아서 "Code"가 든 줄만 남깁니다. 파이프가 없으면 앞 명령 결과가 화면에 다 쏟아지고 끝나지만, 파이프가 있으면 다음 명령이 그 결과를 재료로 받아 가공할 수 있습니다.

grep (추가로 알게 된 것)
넘겨받은 결과에서 특정 글자가 든 줄만 남기는 필터입니다. Linux/macOS 명령어이고 PowerShell에는 없어서, Windows에서는 findstr이나 Select-String으로 대체해야 합니다. (오늘 grep을 썼다가 "인식되지 않습니다" 오류가 났던 이유)

막힌 것
PowerShell에서 grep을 쓰면 명령어를 인식하지 못함 → findstr 또는 Select-String으로 대체해야 함
